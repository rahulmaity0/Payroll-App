================================================================================
ATTENDANCE UPLOAD API - BACKEND REFERENCE FOR FRONTEND TEAM
================================================================================
Last Updated: November 17, 2025
Purpose: Daily & Monthly attendance bulk upload via CSV

================================================================================
1. API ENDPOINT
================================================================================
POST /api/hr/attendance/upload
POST /api/hr/upload/payroll (alias)

Method: POST
Content-Type: multipart/form-data
Auth: Required (HR role only)
File Field Name: "payrollFile" ⚠️ CRITICAL - Must use this exact name

================================================================================
2. QUERY PARAMETERS (All Optional)
================================================================================
?mode=daily|monthly          Auto-detected if not provided
?action=preview|append|overwrite   Default: preview
?dedupeStrategy=skip|update|error  Default: skip
?year=2025                   Optional
?month=11                    Optional
?delimiter=,                 Default: comma

================================================================================
3. CSV FORMAT - DAILY MODE
================================================================================
Writes to: DailyAttendance collection

REQUIRED HEADERS:
  - employeeid (or employee_id, emp_id)
  - date (YYYY-MM-DD format)

OPTIONAL HEADERS:
  - status (P|A|LOP|PL|H|WO) - Default: P
  - checkin (HH:mm format, e.g., 09:00)
  - checkout (HH:mm format, e.g., 18:00)
  - hoursworked (decimal, e.g., 8, 8.5)
  - overtimehours (decimal)
  - notes (max 500 chars)

EXAMPLE CSV:
employeeid,date,status,checkin,checkout,hoursworked,overtimehours,notes
EMP001,2025-11-17,P,09:00,18:00,8,0,Regular shift
EMP002,2025-11-17,PL,,,0,0,Sick leave
EMP003,2025-11-17,LOP,,,0,0,Absent

STATUS CODES:
  P   = Present
  A   = Absent
  LOP = Leave Without Pay
  PL  = Paid Leave
  H   = Holiday
  WO  = Week Off

================================================================================
4. CSV FORMAT - MONTHLY MODE
================================================================================
Writes to: Attendance collection (legacy)

REQUIRED HEADERS:
  - employeeid
  - month (1-12)
  - year (e.g., 2025)
  - totalworkingdays
  - dayspresent

OPTIONAL:
  - leavewithoutpay
  - overtimehours
  - variableearnings (JSON array)
  - variabledeductions (JSON array)

================================================================================
5. AUTO-DETECTION LOGIC
================================================================================
Backend auto-detects mode by inspecting CSV headers:
  - Contains "date" → DAILY mode
  - Contains "month" AND "year" → MONTHLY mode
  - Cannot detect → Returns 400 error

================================================================================
6. VALIDATION RULES
================================================================================
DAILY MODE:
  ✓ Date format: Must be YYYY-MM-DD (e.g., 2025-11-17)
  ✓ Status: Must be one of P, A, LOP, PL, H, WO (uppercase)
  ✓ Check-in/out: Must be HH:mm format (e.g., 09:00, 18:30)
  ✓ Hours: 0-24 for hoursworked, ≥0 for overtimehours
  ✓ Employee: Must exist in database (lookup by employeeId or email)
  ✓ Unique constraint: (employee, date) combination must be unique

MONTHLY MODE:
  ✓ Month: 1-12
  ✓ Year: Valid 4-digit year
  ✓ Working days: Must be > 0
  ✓ Days present: 0 to totalWorkingDays

================================================================================
7. ACTION MODES
================================================================================
PREVIEW (default):
  - Validates CSV
  - Checks for errors
  - Does NOT write to database
  - Returns success/error counts
  - Use for validation before actual upload

APPEND:
  - Writes to database
  - Handles duplicates per dedupeStrategy
  - Default behavior for normal uploads

OVERWRITE:
  - Deletes existing records first
  - Then writes new data
  - Use with caution

================================================================================
8. DEDUPE STRATEGIES
================================================================================
SKIP (default):
  - If record exists → Skip, increment skipped count
  - No error thrown

UPDATE:
  - If record exists → Update with new data
  - Uses UPSERT operation

ERROR:
  - If record exists → Add to errors array, increment failed count
  - Continues processing other rows

================================================================================
9. REQUEST EXAMPLE (JavaScript/Fetch)
================================================================================
const formData = new FormData();
formData.append('payrollFile', fileObject);

const response = await fetch(
  'http://localhost:5000/api/hr/attendance/upload?mode=daily&action=preview&dedupeStrategy=skip',
  {
    method: 'POST',
    headers: {
      'Authorization': 'Bearer YOUR_JWT_TOKEN'
      // Do NOT set Content-Type - browser adds multipart boundary automatically
    },
    body: formData
  }
);

const result = await response.json();

================================================================================
10. SUCCESS RESPONSE (200/201)
================================================================================
{
  "message": "Processing complete",
  "mode": "daily",
  "action": "preview",
  "processed": 40,
  "success": 38,
  "skipped": 2,
  "failed": 0,
  "errors": []
}

Fields:
  - processed: Total rows attempted
  - success: Successfully processed
  - skipped: Skipped due to duplicates (when dedupeStrategy=skip)
  - failed: Failed validation/processing
  - errors: Array of error messages with row numbers

Status Codes:
  - 200: Preview mode or read-only
  - 201: Data written successfully (append/overwrite mode)

================================================================================
11. ERROR RESPONSE EXAMPLES
================================================================================

  "message": "Please upload a CSV file"

================================================================================
12. BACKEND PROCESSING FLOW
================================================================================
1. Receive file with field name "payrollFile"
2. Parse query parameters (mode, action, dedupeStrategy)
3. Read CSV first line to detect headers
4. Normalize headers to lowercase
5. Auto-detect mode if not provided
6. Validate required headers exist
7. Process each CSV row:
   a. Normalize column keys
   b. Lookup employee by employeeId or email
   c. Validate date/status/fields
   d. If preview → count success, skip write
   e. If append/overwrite → write to database
   f. Handle duplicates per dedupeStrategy
   g. Collect errors with row numbers
8. Delete uploaded file from server
9. Return response with counts and errors

================================================================================
13. COMMON FRONTEND MISTAKES TO AVOID
================================================================================
❌ Using field name 'file' instead of 'payrollFile'
❌ Setting Content-Type header manually (breaks multipart boundary)
❌ Not including Authorization header
❌ Using wrong date format (e.g., DD/MM/YYYY instead of YYYY-MM-DD)
❌ Using lowercase status codes (e.g., 'p' instead of 'P')
❌ Not handling partial success (some rows succeed, some fail)
❌ Expecting 201 for preview mode (should be 200)

================================================================================
14. DATABASE COLLECTIONS
================================================================================
DAILY MODE → DailyAttendance collection
  Schema: {
    employee: ObjectId (ref Employee),
    date: String (YYYY-MM-DD),
    status: String (P|A|LOP|PL|H|WO),
    checkIn: String (HH:mm),
    checkOut: String (HH:mm),
    hoursWorked: Number (0-24),
    overtimeHours: Number (≥0),
    notes: String (max 500)
  }
  Unique Index: (employee, date)

MONTHLY MODE → Attendance collection
  Schema: {
    employee: ObjectId,
    month: Number (1-12),
    year: Number,
    totalWorkingDays: Number,
    daysPresent: Number,
    leaveWithoutPay: Number,
    overtimeHours: Number,
    variableEarnings: Array,
    variableDeductions: Array
  }
  Unique Index: (employee, month, year)

================================================================================
15. EMPLOYEE LOOKUP LOGIC
================================================================================
Backend tries multiple lookup strategies:
1. If empKey contains '@' → Search by email (personalEmail or email field)
2. Else → Search by employeeId field
3. If not found → Add error "Employee X not found" and skip row

Supported CSV column names for employee:
  - employeeid
  - employee_id
  - emp_id
  - email

16. TESTING CHECKLIST
================================================================================
□ Valid daily CSV with all fields → Success
□ Valid daily CSV with only required fields → Success
□ Preview mode → Returns 200, no DB writes
□ Append mode → Returns 201, writes to DB
□ Duplicate records with skip strategy → Increments skipped count
□ Duplicate records with update strategy → Updates existing
□ Duplicate records with error strategy → Adds to errors array
□ Invalid date format → Returns error with row number
□ Invalid status code → Returns error with row number
□ Non-existent employee → Returns error with row number
□ Missing required headers → Returns 400 error
□ Wrong file field name → Returns "Please upload a CSV file"
□ Missing auth token → Returns 401
□ Non-HR user → Returns 403
