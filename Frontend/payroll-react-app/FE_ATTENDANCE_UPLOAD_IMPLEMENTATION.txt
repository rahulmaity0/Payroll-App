================================================================================
1. API ENDPOINT CONFIGURATION
================================================================================

Base URL: http://localhost:5000/api (from .env REACT_APP_API_BASE_URL)

Upload Endpoint: POST /api/hr/attendance/upload

Query Parameters Sent:
- mode: 'daily' | 'monthly' (default: 'daily')
- action: 'preview' | 'append' | 'overwrite' (default: 'preview')
- dedupeStrategy: 'skip' | 'update' | 'error' (default: 'skip')
- delimiter: string (default: ',')
- year: number (optional, for monthly mode)
- month: number (optional, for monthly mode)

Example URL:
http://localhost:5000/api/hr/attendance/upload?mode=daily&action=preview&dedupeStrategy=skip

================================================================================
2. REQUEST FORMAT
================================================================================

Method: POST
Content-Type: multipart/form-data (auto-set by browser with boundary)

Headers:
{
  "Authorization": "Bearer <JWT_TOKEN>"
  // Content-Type NOT manually set - browser handles it
}

FormData Field:
- Field Name: "payrollFile" (CRITICAL: must match backend expectation)
- File: CSV file object
- Filename: Original filename preserved

Code Implementation:
```javascript
const formData = new FormData();
formData.append('payrollFile', file, file.name);

fetch(url, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
  body: formData
});
```

================================================================================
3. CSV FILE FORMAT SENT
================================================================================

Daily Format (Default):
Headers (lowercase): employeeid,date,status,checkin,checkout,hoursworked,overtimehours,notes

Example CSV Content:
```csv
employeeid,date,status,checkin,checkout,hoursworked,overtimehours,notes
EMP001,2025-11-16,P,09:00,18:00,8,0,Regular shift
EMP002,2025-11-16,PL,,,0,0,Sick leave
EMP003,2025-11-16,LOP,,,0,0,Leave without pay
```

Required Headers: employeeid, date
Optional Headers: status, checkin, checkout, hoursworked, overtimehours, notes

Status Codes Used: P, A, LOP, PL, H, WO

File Characteristics:
- Encoding: UTF-8 (no BOM)
- Line Endings: LF (\n) or CRLF (\r\n)
- Delimiter: Comma (,)
- Max Size: 5MB (validated client-side)
- Format: .csv only (validated client-side)

================================================================================
4. EXPECTED BACKEND RESPONSE FORMAT
================================================================================

Success Response (200 OK for preview, 201 Created for writes):
```json
{
  "message": "Processing complete",
  "mode": "daily",
  "action": "preview",
  "processed": 40,
  "success": 38,
  "failed": 2,
  "skipped": 0,
  "errors": [
    "Row 5: Invalid date format",
    "Row 12: Employee EMP999 not found"
  ]
}
```

Field Names Expected:
- message: string
- mode: 'daily' | 'monthly'
- action: 'preview' | 'append' | 'overwrite'
- processed: number (total rows processed)
- success: number (rows that passed validation/saved)
- failed: number (rows that failed validation)
- skipped: number (optional, duplicate rows skipped)
- errors: string[] (array of error messages)

Error Response (400 Bad Request):
```json
{
  "message": "CSV missing required daily headers: employeeid, date"
}
```

================================================================================
5. FRONTEND VALIDATION (Pre-Upload)
================================================================================

Client-Side Checks:
1. File type: Must be .csv (rejects .xlsx, .xls, etc.)
2. File size: Must be ≤ 5MB
3. File selected: Non-null file object required
4. Authentication: JWT token must exist

Validation Errors Shown to User:
- "Please upload a CSV file only"
- "File size exceeds 5MB limit (current: X.XX MB)"
- "Please select a file"
- "Not authenticated"

NO client-side CSV parsing - all validation done by backend.

================================================================================
6. USER WORKFLOW
================================================================================

Step 1: SELECT MODE
- Daily (default) - for day-by-day records
- Monthly - for aggregate summaries
- Auto - let backend auto-detect (deprecated, not used)

Step 2: SELECT ACTION
- Preview (default) - validate only, no database writes
- Append - insert new records (respects dedupeStrategy)
- Overwrite - replace existing data

Step 3: UPLOAD FILE
User can:
a) Download template (generates CSV with correct headers)
b) Upload custom CSV file

Step 4: PREVIEW
- Sends action=preview
- Backend validates all rows
- Shows: processed, success, failed counts
- Displays error messages if any
- NO database changes

Step 5: COMMIT (if preview successful)
- Sends action=append or action=overwrite
- Backend saves to database
- Shows success message
- Navigates to attendance page after 2.5s

================================================================================
7. ERROR HANDLING
================================================================================

Network Errors:
- "Cannot connect to server at http://localhost:5000. Please ensure backend is running."

Backend Errors (from response.message):
- "CSV missing required daily headers: employeeid, date"
- "Invalid date format"
- "Employee not found"
- "Upload failed with status XXX"

Display Strategy:
- Preview errors: Show error count + first 10 error messages
- Commit errors: Show error message, don't navigate
- Network errors: Show connection error
